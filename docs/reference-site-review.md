# 参考站对比与改造验收

核验日期：2026-10-01（北京时间）。本文记录实际实现与验证，不把来源配置数当成论文完整率。

## 1. 严格限定 CCF A/B

本次范围为 CCF 2026 第七版：58 个 A 类会议、132 个 B 类会议、37 个 A 类期刊、111 个 B 类期刊，合计 **338 个去重后的来源**。不增加 C 类、目录外会议或期刊。TOMM、DKE 的跨领域重复条目各保留一个来源，完整领域证据保存在 `seeds/ccf_catalog_provenance.json`。

同缩写不等于同一来源：例如软件工程 FSE 与密码学 FSE 分别配置；会议与同名期刊也分别配置。来源的 CCF 学科领域和论文研究主题是独立维度，不能把所有来源都归为人工智能。

本地迁移检查：40 → 338 个来源，非 A/B 来源 **0**；现有论文元数据和人工标签未被种子迁移覆盖。

## 2. 参考站实际采用什么方案

参考站是预生成 JSON 驱动的静态单页应用，不是访客打开页面时实时抓取论文：

- A/B 会议与 A/B 期刊分别有概览数据，范围切换会改变计数与主题分布。
- 首页先读取轻量 `index.json`；进入具体来源后按需读取该来源的论文 JSON。
- 全局检索索引也是按需加载；例如 A 类会议的 `global_index.json` 原始大小约 14.6 MB。因此它的首页很轻，不代表第一次全局检索没有额外下载。
- 截稿数据来自 CCFDDL；网站自己的说明也要求最终确认会议官网。
- 不同数据集的年份覆盖不同，自动主题分类和总篇数不能直接当作正式发表全量基准。

参考站源码未声明许可，本次没有复制其 JS/CSS 实现。借鉴的是分层加载、范围独立统计与投稿日历的信息结构；目录来自 CCF 文件，截稿信息来自带 MIT 许可的 CCFDDL。

## 4. 加载方案与日历

保留已有离线阅读架构，不引入依赖常驻后端的公开站点。

- overview v2 只保存一次来源名称等元数据，各 scope 仅保存计数与年份。来源主题预计算；首页与来源地图不读取论文分片。
- 首屏仍是 manifest + catalog 两份文件，本快照共 **480,693 字节**，低于 512 KiB 验收预算。
- 重访先从浏览器 Cache Storage 恢复经 SHA-256 校验的原始概览，再后台检查版本；损坏、禁用或超时的缓存回退到网络。缓存保存原始 JSON 文本，避免 JavaScript 重新排序数字形态的索引桶键导致散列失效。
- 按来源、年份、级别或方向浏览时，利用已验证的 ID 范围只读取可能匹配的卡片分片；筛选和分页仍由共享引擎精确执行。旧版读取器仍可回退。
- 标题/摘要检索继续按词项/标题桶按需加载，不退回到参考站那种整份全局索引下载方式。

日历 `#/deadlines` 提供月历/列表、A/B 与领域筛选、各轮次、摘要截止提示、北京时间/UTC 和当前结果 `.ics` 导出。当前独立快照包含 **388 个轮次、181 / 190 个会议的当年或未来届次**。

AoE 为 UTC−12。日期统一转换，不能把原时区的“23:59”直接按北京时间显示。TBD、不完整日期和无法确定的时区不猜测；期刊不混入会议截稿日历；同缩写/共享 DBLP 路径不模糊串配，特别测试了 ACM SoCC 与 IEEE Cloud。

日历为社区汇总而非逐条官网核验，展示同步时间、原时区、官网与社区数据出处，超过 7 天提示过期。Pages 构建尝试同步，失败保留带日期的旧数据；`.ics` 是导出，不是自动更新订阅。MIT 许可随静态资源分发。
