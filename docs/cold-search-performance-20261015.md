# 冷搜索优化验收（2026-10-15）

验收时间：2026-10-15 23:00:12（Asia/Shanghai）。**状态：本地已实现、已验证；本轮尚未推送或部署。**

## 1. 最终方案与边界

基线提交 `8b5951a`；最终运行时代码提交 `1e25b1e`，分支 `codex/cold-search-performance-20261015`。

最终只优化静态快照 Worker 的检索实现，不修改数据库、论文、来源归属、界面组件或既有 React Query 缓存策略：

1. 完整标题索引与词项索引独立并行加载，仍使用原来的六路共享下载池和取消机制。
2. 排序分片仍按原范围下载，并在首个查询结束前完成全部排序行的校验与解码；不把下载、解码或行构造成本推迟给首次目录操作。
3. 每行只复制一次，避免原来的过滤数组、切片和展开临时对象；原始校验数据不修改。
4. 建立紧凑的 Uint32/Float64 ID 索引，小候选集二分定位，大候选集扫描。不相交区间由边界保证唯一性，重叠区间仍拒绝重复 ID；无效的页外 ID 仍报错。
5. 每个词组 IDF 只计算一次，并简化单词短语判断；全局 BM25、精确标题优先级、AND、模糊检索和分页语义不变。

**原快照 `3873cffb758d17191320959552880fbfa9a82ebfa8bb3a82651b5d98f9dad140` 已按字节恢复并保留。** 381,441 篇论文及来源关联不变；无需为最终优化重新导出或上传数据。

## 4. 明确淘汰的方案

最初试验过跳过普通搜索的排序表下载。虽然首次搜索更快，但独立前台 A/B 复核发现：4 Mbps 条件下首次目录切换中位数由 **809 ms 增至 1,942 ms**。该方案不满足“保留原有速度”的要求，已从最终代码和活动快照中移除，没有部署。

随后也取消了延迟构造排序行的做法，恢复“首个结果前一次性解码，后续直接复用”，并增加了原始行访问计数回归测试。此前的快照、原始统计和失败记录留在忽略的本地验收目录，不能当作最终版本的收益。减少动画干扰的中间对照也仅作诊断，不替代以上最终版本结果。
