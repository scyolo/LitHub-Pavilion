## 后端搜索

原实现为每条候选记录启动一次 FTS5 排名查询，重复初始化整个语料的 BM25 统计。现在一次收集去重候选 ID、一次计算匹配记录的排名，再进行筛选和分页。元数据准入采用有上限的纯函数缓存，缓存键包含全部判定输入；修改标题、DOI、出版方身份、DBLP 身份或来源后立即生效。

测量使用同一真实数据库的只读连接、直接调用 API 查询函数；不包含 HTTP 或公网延迟。每种查询先清空元数据判定缓存，随后重复五次，报告重复查询中位数。SQLite 文件页和 Python 进程可能已经预热，首次列不代表操作系统冷启动。

| 查询 | 修改前观察值 | 修改后首次 | 修改后重复中位数 |
| --- | ---: | ---: | ---: |
| `learning` + ICML / 2025 | 5,925–5,968 ms | 269 ms | 229 ms |
| `speculative decoding` | 150–165 ms | 23 ms | 15 ms |
| `speculativ decodng` | 581–623 ms | 347 ms | 342 ms |
| 完整标题 `Attention Is All You Need` | 3–43 ms | 5 ms | 2 ms |
| `learning`，全部来源 | 排名阶段超过 10 秒后中断 | 3,398 ms | 1,798 ms |

组合词、错拼和筛选查询的总量、首屏 ID 及顺序与原实现一致。回归测试另核对全局 BM25 分数、分页、精确/Unicode 标题召回与编辑后的缓存有效性。宽泛词的首次后端查询仍需数秒，不能把小候选集的速度推广到所有查询。

## 浏览器页面

弱网检查发现，重复查询已经命中缓存，但返回首页时的图表、来源矩阵排版仍会拖慢随后的页面切换。现已复用固定语言与时区的数字／日期格式化器，并让首页屏幕外的图表、方向、来源矩阵和底部区域按需排版。页面内容仍完整保留在文档中，浏览器滚动到附近时正常布局。

最终生产构建在本机 Chrome、无额外网络限速下，首页 229 ms；六组浏览／查询首次 367–701 ms、重复 19–55 ms。各项均通过既有预算，未发现页面脚本错误或水平溢出。这些是本机测量值，不代表公网延迟。

390 × 844 移动端已验证搜索结果、全部 338 行来源矩阵的展开与收起、键盘横向滚动、首页最新论文进入详情，以及来源覆盖页面 17 篇会议关联论文的展开；无失败请求、脚本错误或页面水平溢出。

采用共享带宽 4 Mbps、80 ms 额外延迟、主线程 4 倍 CPU 限速的原有浏览器脚本，最终构建的结果如下。首页和首次查询全部通过既有预算，但重复浏览和错拼查询超过 800 ms，**弱网性能预算未全部通过**；未放宽阈值，也未用单独复测覆盖这些失败记录。
